### 과제 배경:
- 현재 저는 AX 교육에 투입되어 마지막 과정으로 0.5일 기획(문서 작성)을 하고 1.5일간 미니 프로젝트를 개발해야 됩니다.
- 미니 프로젝트는 AI 에이전트를 만드는 것입니다.

### 배경 기술:
- 회사에서 프로젝트를 시작하면 문서관리 시스템으로 컨플루언스를 사용합니다.
- 컨플루언스에 온보딩 매뉴얼과 프로젝트에 관련된 문서들을 정리하고 공유합니다.

### 아이디어 초안:
##### 페인 포인트
- 온보딩이 된 신입 멤버의 경우, 프로젝트의 온보딩 매뉴얼을 찾기 어렵습니다.
  예1: 방화벽 설정, 보안 설정, 프로젝트 시스템들과 가입 및 사용 신청 등등 ...
- 온보딩이 된 신입 멤버의 경우, 프로젝트의 기본 정보를 찾아서 업무를 파악해야 합니다.
  예2: 이미 개발이 시작된 경우, 개발환경 구축 가이드 등을 찾아서 환경 구축도 해야 합니다.
- (소크라테스 문답으로 구체화) 현재는 막히면 사수/멘토에게 메신저로 물어봅니다. 응답 자체는 빠르지만(체감 5분 이내), 문제는 속도가 아니라 매번 다른 사람의 업무를 끊어야 하고 셀프서비스가 안 된다는 점입니다.
- (구체화) 셀프서비스로 직접 찾아보더라도, 개발환경 가이드처럼 긴 문서는 필요한 내용이 어디 있는지 몰라 처음부터 끝까지 한 줄 한 줄 꼼꼼히 읽어야 합니다.
- (구체화) 프로젝트 도중에 합류한 신입은 애초에 어떤 문서부터 어떤 순서로 봐야 하는지도 모릅니다.
- **대상 사용자 규모**: 연간/분기 기준 약 10~50명(중규모)의 신입이 새 SI/SM 프로젝트에 투입되는 것을 가정합니다. PoC는 프로젝트별 개별 인스턴스로 운영하고, 효과가 검증되면 전사 공유 서비스로 확장합니다.
##### 아이디어
- 컨플루언스 MCP를 AI 에이전트에 채택해서 공개된 API를 호출하여 상호작용을 하려고 합니다.
- 테스트를 위한 문서관리 프로젝트는 기존에 존재하는 오픈소스 프로젝트의 오픈된 컨플루언스를 대상으로 하려고 합니다.
  예3: 잠정적으로 Apache Software Foundation 의 컨플루언스를 생각하고 있습니다.
  → **확정**: Apache Hadoop의 `HADOOP2` 공간(cwiki.apache.org/confluence/display/HADOOP2)으로 확정. 인증 없이 REST API 접근 가능함을 확인했고, 개발환경 설정/커밋/코드리뷰/릴리즈 절차 등 온보딩과 유사한 실제 문서 7건을 확인했습니다.
- 언어는 파이썬이고 langchain, langgraph 라이브러리를 쓸 것입니다.
- ai 에이전트 파트와 모델 서빙을 위한 fastapi 를 활용한 서버 파트, 그리고 서버를 호출하는 UI 부분인 html 파트로 나누어서 구현을 하려고 합니다.
  → **확정**: 여기에 "크롤링 & RAG 구축 파트"를 더해 4파트로 구성합니다 — `crawl_confluence.py`(크롤링) + `src/retriever.py`(RAG) + `src/tools.py`(Confluence MCP 서버) + `src/agent.py`(에이전트) + `server.py`(FastAPI) + `static/chat.html`(UI). 자세한 구조는 `CLAUDE.md` 참고.
- html 파트는 채팅 UI로 필요한 라이브러리들은 직접 include를 해서 html 파일 하나로 구현을 했으면 합니다.
- **(신규) 검색 아키텍처**: RAG(사전 크롤링한 20~30개 페이지 임베딩) 검색을 우선하고, 결과가 부족하면 MCP로 컨플루언스를 실시간 검색(CQL)하는 폴백을 에이전트가 자율 판단해 수행합니다. 그래도 못 찾으면 "모른다"고 답합니다.
- **(신규) 언어 정책**: 답변 요약은 한국어로 쓰고, 출처 인용구는 영어 원문 그대로 남겨 번역 오류로 인한 정보 왜곡을 막습니다.
- **(신규) 실무 교체 가능성**: Confluence base URL/인증 토큰을 `.env`로 빼서, 설정만 바꾸면 사내 컨플루언스로 바로 교체 가능한 구조로 만듭니다.
