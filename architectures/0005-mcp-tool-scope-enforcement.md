# 0005. 도구 실행 범위(스페이스 스코프)는 프롬프트가 아니라 코드로 강제

- 상태: 채택
- 관련 코드: `src/agent/tools.py`의 `search_confluence()`
- 관련 문서: `data/documents/ISSUES.md` 4절

## 맥락
평가 중 "Kafka 클러스터에 새 Topic을 만드는 방법"(범위밖으로 기대한 질문)에 에이전트가 `AdminClient` 코드까지 곁들인 상세한 답을 내놓은 사례가 있었습니다. 처음에는 모델이 사전 지식(pretrained knowledge)으로 답한 환각으로 의심했지만, `trace`를 실제로 뜯어본 결과 원인은 달랐습니다: `search_confluence`가 호출자의 CQL을 스페이스 제한 없이 그대로 실행하고 있어서, `cwiki.apache.org` 전체(HADOOP2뿐 아니라 실제 KAFKA 프로젝트 스페이스까지)를 검색해 진짜 KIP 문서를 찾아 답한 것이었습니다 — 환각이 아니라 **스코프 위반**이었습니다.

## 결정
`search_confluence(cql)`이 호출자가 보낸 CQL을 그대로 실행하지 않고, 서버 쪽에서 `space = "{CONFLUENCE_SPACE_KEY}" AND (...)`로 강제로 감싸도록 고쳤습니다. `CONFLUENCE_SPACE_KEY`는 `.env`로 교체 가능하며 기본값은 `HADOOP2`입니다. 즉 "에이전트가 스페이스 조건을 CQL에 넣는 것을 잊지 않기를" 기대하는 프롬프트 지침이 아니라, 도구 코드 자체가 범위를 보장하도록 만들었습니다.

## 결과/트레이드오프
- **장점**: 프롬프트를 아무리 강화해도 모델이 매번 지침을 정확히 따른다는 보장은 없지만, 도구 코드의 강제는 100% 결정적입니다. 이 사례를 계기로 일반화한 교훈은 "안전장치는 설득(프롬프트)이 아니라 강제(코드)에 두는 게 신뢰할 수 있다"는 것이고, 이후 다른 안전장치를 설계할 때도 이 원칙을 우선 적용합니다.
- **단점**: 스코프를 하나의 환경변수(`CONFLUENCE_SPACE_KEY`, 스페이스 하나)로 고정하고 있어서, 여러 스페이스를 넘나들며 검색해야 하는 요구가 생기면 이 강제 로직 자체를 다시 설계해야 합니다(예: 허용 스페이스 목록으로 확장).
- **아직 남은 위험**: 이번에 고친 것은 `search_confluence`(실시간 검색) 경로뿐입니다. `get_page`(URL/ID로 직접 조회)는 애초에 호출자가 URL을 지정하므로 같은 종류의 스코프 누락 위험은 낮지만, 새로운 MCP 도구를 추가할 때마다 "이 도구도 스코프를 코드로 강제하고 있는가"를 체크리스트로 확인해야 합니다.
